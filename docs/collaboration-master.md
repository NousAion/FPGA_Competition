# 项目协作总控文档

本文件是三名队员和三个 Codex 会话的共同工作约定。它只解决三件事：每次做什么、可以改哪些文件、怎样证明做完。详细接口以 [interfaces-v0.md](interfaces-v0.md) 为准，当前任务以 [task-board.md](task-board.md) 为准。

## 1. 当前目标

- 平台：Tang Mega 138K C 版 + Tang Mega 138K Dock。
- 近期目标：板卡到货后先完成固定测试音，再逐步接入音频核心。
- 基础要求是硬目标；扩展 1、2 是主线；扩展 3 只在基础链路稳定后尝试。
- 音频主链路必须由 FPGA HDL 逐样本生成，不使用 AE350、上位机或预录 PCM。

## 2. 第一轮任务认领

每个人只认领一项，单项目标控制在 1～2 小时。每项都必须包含“RTL + testbench + 简短交接说明”，不把查资料、写文档或测试固定分给某个人。

| 任务 | 认领人 | 允许修改 | 完成判据 |
|---|---|---|---|
| T-001 相位累加器 | ______ | `rtl/audio/phase_accumulator.v`、`tb/phase_accumulator_tb.v` | 复位、`sample_ce`、步长改变、8 位测试回绕通过 |
| T-002 ADSR 包络 | ______ | `rtl/audio/adsr_envelope.v`、`tb/adsr_envelope_tb.v` | IDLE/ATTACK/DECAY/SUSTAIN/RELEASE 可重复观察 |
| T-003 混音限幅 | ______ | `rtl/audio/mixer_saturator.v`、`tb/mixer_saturator_tb.v` | 普通相加、正溢出、负溢出通过 |

T-001 已有基线实现，认领人首先负责运行、读懂和 review；不要重复重写。T-002、T-003 未完成时，只能从最新 `main` 创建分支实现。

## 3. AI 会话的统一提示词

每次给 Codex 的第一条消息都使用下面的格式：

```text
任务 ID：T-00X
目标：只完成这一项，预计不超过 2 小时
允许修改：<文件列表>
禁止修改：其他 RTL、顶层、工程文件、约束文件
接口：严格遵守 docs/interfaces-v0.md
完成条件：<列出 testbench 必须检查的情况>
如果接口不足：先报告，不要自行改接口
完成后报告：修改文件、测试命令、测试结果、未解决问题
```

AI 不得被要求“继续完善项目”“顺便修改其他模块”或“直接完成电子乐器”。每个会话只处理一个任务卡。

## 4. 不可擅自改变的共识

1. 时序模块统一使用 `clk`、低有效异步复位 `rst_n` 和单周期 `sample_ce`。
2. 音频内部样本统一为 24 位有符号定点；相位累加器为 32 位无符号。
3. T-001/T-002/T-003 的端口以 `interfaces-v0.md` 为唯一标准。
4. 模块内部发现接口不够时，先提出问题；适配逻辑放在后续集成层。
5. 第一轮不接真实传感器、不改正式 I2S 引脚、不加入 DDR3/AE350/效果器。
6. 任何人都不直接修改别人的任务文件；顶层和 `.gprj` 只能由集成任务单独修改。
7. 每项任务的负责人同时负责该模块的资料、testbench 和交接说明，不建立“一个人只查资料”的弱相关岗位。

## 5. Git 分支和交接

建议分支名：

```text
feat/t001-phase
feat/t002-adsr
feat/t003-mixer
```

提交前必须执行：

```powershell
git status
git diff --check
```

提交信息只做一件事，例如：

```text
feat: add ADSR envelope
test: verify mixer saturation
```

提交报告必须包含：

- 修改了哪些文件；
- 是否改变接口；
- 使用的仿真工具和命令；
- 仿真是否通过；
- 仍存在什么风险。

合并顺序固定为：负责人提交 → 另一名队员 review → 在 `main` 上综合/集成。共享同一工作目录时，不要两个人同时编辑文件；最好每人使用独立 clone 或 worktree。

## 6. 板卡到货后的集成顺序

1. 确认 C 版丝印、Gowin Programmer 识别和官方约束。
2. 建立独立固定测试音顶层，验证 I2S、耳机口和扬声器；`PA_EN=0` 才开启功放。
3. 将 T-001 接到简单波形发生器，完成单声部仿真和上板验证。
4. 接入 T-002 包络，再接 T-003 混音，形成 4 声部基础链路。
5. 集成任务完成前，T-001/T-002/T-003 不再改接口；需要变化时新增适配模块。

## 7. 每日同步格式

每个人结束工作时只发四行：

```text
完成：
验证：
阻塞：
下一步：
```

没有完成也要提交当前状态，不要为了“看起来完成”而扩大任务范围或删除失败测试。
