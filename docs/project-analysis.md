# 高云 FPGA 选题二：实时多音色合成电子乐器引擎

## 1. 分析范围与资料结论

本分析基于 `D:/qqdownload/FPFG_COMPETITION` 中的高云 2026 FPGA 赛道选题指南、FPGA2026 赛题解读资料、Sipeed Tang 系列资料及当前 Gowin 工程文件。当前工程目标器件为已确认的 **Tang Mega 138K C 版普通 PG484 SOM**：`GW5AST-138C / GW5AST-LV138PG484AC1/I0`。现有 RTL 仍只有一个 `mux_2` 组合逻辑例程，尚未实现赛题功能。

赛题核心是：用 FPGA HDL 完成从演奏交互采集到 I2S 音频输出的纯硬件实时合成链路。音频不能依赖软核、MCU、上位机或预录 PCM；输出必须由实时控制量逐样本、逐声部生成。

## 2. 赛题验收指标

### 基础要求（必须闭环）

1. 至少 2 个独立可控演奏维度，例如音高/按键与力度，或音高与滑音/音色。
2. 交互动作能被 FPGA 稳定解析为选音、触发、拨弦、力度等控制事件。
3. FPGA HDL 完成实时音频合成，可选波表、加法合成、FM 或物理建模。
4. 通过 I2S 输出到 DAC/音频解码器。
5. 基础复音数不少于 4，支持独立声部同时发声。
6. 控制信号到音频输出总延迟不超过 10 ms。
7. 禁止直接播放预录 PCM、预置推流或整段录音触发。

### 扩展目标与优先级

按官方编号拆分，项目计划如下：

- **扩展 1（主线）**：复音数达到 32，或使用不少于 32 个独立加法合成分量/并行建模单元。项目的高密度架构目标是 4 声部 × 32 个独立合成分量，即最多 128 个可计数振荡器；这属于在资源、时序和音质验证通过后的冲刺目标，扩展 1 的最低验收门槛仍是 32 个独立单元。
- **扩展 2（主线）**：至少 3 维表情控制、至少 2 种音色切换，并在 FPGA 内实现至少一种延迟/混响/合唱效果。内部拆成 2a/2b/2c 分项验收，避免只完成音色切换却误称整项完成。
- **扩展 3（冲刺）**：演奏延迟 ≤5 ms、确定性无抖动，并完成 LED、波形、频谱或李萨如图中的至少一种硬件反馈。
- **扩展 4（暂不纳入主线）**：脱机曲目指引、蓝牙或手机 App 联动。

“至少完成一项扩展”是项目进度兜底，不是赛题硬性门槛；主线仍按扩展 1+2 设计。

扩展 1 的统计必须遵循官方现场口径：可计数的独立发声单元需有独立相位累加器、频率控制和包络控制；单纯增加波表谐波不重复计数。测试模式应让 32 个单元输出彼此可分辨的频率，并保留频谱、RTL 层级和综合报告作为证据。扩展 2 只有在三维表情、双音色和 FPGA 内效果器三个子项全部闭环后，才在答辩材料中标记为“已完成”。

### Tang Mega 138K 资源定位

普通 PG484 版约有 138,240 LUT/FF、298 个 18×18 DSP、6,120 Kbit BSRAM 和 12 个 PLL；板载 DDR3 容量/速率以实际 SOM 与 BOM 为准，首版音频链路不依赖 DDR3。资源余量用于至少 4 声部、三维表情、双音色和效果器，并在验证通过后冲刺 4 声部 × 32 分量的高密度架构；AE350、PCIe 和 SerDes 不进入音频主链路，不能替代 FPGA HDL 合成。

## 3. 建议的系统链路

```text
交互传感器/按键
        │
        ▼
12 键钢琴式/实体按键 ──► 去抖/滤波与参数标定
        │                         ▲
        ├── 压力检测/旋转控制/可选电容触控 ─┘
        │                         │
        └──────────────► 演奏事件总线（note/velocity/gate/expr）
                                      │
                                      ▼
                            声部管理器（至少 4，主线目标 32）
                                      │
                                      ▼
             音高相位累加器 + 波表/加法/FM 振荡器 + ADSR 包络
                                      │
                                      ▼
                               多声部混音与限幅
                                      │
                                      ▼
                               音频效果器（扩展 2 主线，可旁路）
                                      │
                                      ▼
                   音频采样时序/左右声道打包 + I2S TX
                                      │
                                      ▼
                                  DAC/功放/扬声器

并行旁路：事件/音频状态 ─► LED/显示/频谱/波形可视化（扩展 3 冲刺）
```

交互方案按阶段落地：钢琴式按键或实体按键是主要输入，负责音符选择、和弦和触发；压力检测
负责力度；旋转或其他连续控制器负责滑音、颤音或音色参数。APDS-9960 可作为可选的 I2C
扩展输入，提供手势、接近度、RGB/环境光数据，映射到滑音、颤音、音色或效果深度；它不替代
按键和压力传感器，也不直接输出高精度压力值。电容触控仍作为可选辅助输入。
扩展 2 的三个表情维度必须分别映射到可验证的控制信号；只有一个旋转编码器通过模式切换
复用多个参数时，不能直接宣称三个维度同时独立成立。12 键键盘、压力检测和连续控制器的
具体电气接口和扫描时序须以实物与原理图验证结果为准。

### 3.1 时钟与采样坐标系

- `clk_sys`：FPGA 主时钟，负责输入、控制和音频流水线。
- `sample_tick`：音频采样使能，建议先以 48 kHz 为设计基准。
- `bclk`、`lrck`、`sdout`：I2S 位时钟、左右声道字选择和串行数据。
- 所有声部相位、包络和效果器状态只在 `sample_tick` 更新，避免不同模块各自计时造成漂移。
- 输入事件在 `clk_sys` 域采集并通过单一事件 FIFO/握手接口送入音频域；跨时钟域必须使用同步器或异步 FIFO。

### 3.2 数据格式约定（初版）

- 音频内部统一使用有符号定点数，建议 Q1.23 或 Q4.20；模块接口不得混用无符号音频值。
- `note_id` 使用 MIDI 风格整数音高；`phase_inc` 由音高查表或定点公式产生。
- `velocity`、表情参数和增益均使用明确位宽及饱和规则。
- 混音前保留足够保护位，混音后统一限幅/舍入到 I2S 输出位宽。

## 4. 模块边界

### 4.1 `rtl/io`

- `key_matrix_scan` / `touch_scan`：按键、电容或自研传感器采集。
- `input_debounce`：去抖、稳定判定。
- `sensor_calibration`：零点、阈值和力度标定。
- `i2s_tx`：标准 I2S 主机发送；先完成单音测试，再接入混音链路。

### 4.2 `rtl/control`

- `event_decoder`：把输入变化转换为 `NOTE_ON`、`NOTE_OFF`、力度和表情事件。
- `voice_manager`：空闲声部分配、抢占策略、释放状态管理。
- `instrument_ctrl`：音色选择、全局增益、效果器开关。
- `event_fifo`：将输入域事件与音频采样域解耦。

### 4.3 `rtl/audio`

- `phase_accumulator`：每个声部的相位累加器。
- `wavetable_osc`：正弦/锯齿/方波等查表振荡器；波表是波形数据，不是预录整段音频。
- `additive_osc` / `fm_osc`：扩展合成算法。
- `adsr_envelope`：起音、衰减、保持、释音。
- `voice_core`：单声部控制、振荡器和包络的组合；高密度模式下每个可计数分量保留独立相位、频率和包络/幅度控制。
- `mixer`：多声部求和、保护位、增益缩放和饱和。

### 4.4 `rtl/effects`

- `delay_line`：基于片上 RAM 的短延迟。
- `schroeder_reverb`：可选混响；先做旁路可用，再增加反馈网络。
- `chorus`：可选调制延迟。

### 4.5 `rtl/display` 与 `rtl/common`

- `led_guide`、`waveform_view`、`spectrum_analyzer`：可视化扩展。
- `clock_enable`、`saturator`、`cdc_sync`、`fixed_point_pkg`：所有模块共享的基础单元。

## 5. 推荐实现顺序

1. 保留 `mux_2` 作为最小综合 smoke test；按 138K 器件建立新顶层和板级约束。
2. 从官方 138K `audio_i2s` 例程提取时钟/I2S 时序，完成固定频率测试音，验证 DAC、功放使能和耳机输出。
3. 完成单声部波表振荡器，输入先用寄存器/仿真激励。
4. 接入 `NOTE_ON/OFF`、ADSR 和至少 4 声部混音，先闭环全部基础要求。
5. 接入两种演奏维度，再加入第 3 维表情控制和两种音色切换（扩展 2a/2b）。
6. 按“4 声部 × 每声部 1→8→16→32 分量”的顺序扩展，先达到扩展 1 的 32 个独立单元，再视资源和时序余量冲刺 128 个振荡器；同时增加不同频率谱峰和 RTL 统计证据。
7. 加入 FPGA 内短延迟，随后按资源和时序余量选择 Schroeder 混响或合唱（扩展 2c）。
8. 最后尝试 ≤5 ms 延迟测量与波形/频谱/LED 反馈（扩展 3）；所有扩展都必须可旁路、可测量，不得阻塞基础链路。

## 8. 主要风险与待确认项

1. 已确认实物为普通 Tang Mega 138K PG484、C 版；后续新增 IP 必须针对该器件重新生成。
2. 需要确认板上 DAC/Codec 型号、I2S 主从关系、MCLK 要求和模拟音频输出路径；官方例程的音频引脚只能作为起点。
3. 交互方案目标为 12 键钢琴式/实体按键 + 压力检测 + 连续控制器；为降低周期风险，首版先完成按键与压力两维闭环，再增加滑音、颤音或音色参数的第三维，并允许用等效输入适配器先验证音频核心。电容触控作为可选辅助方案。
4. 138K 资源足以支撑主线扩展，但 DDR3 不作为首版依赖；短延迟优先使用片上 BSRAM，避免引入 DDR 控制器时序风险。
5. 32 声部、效果器和显示仍会增加时序压力，必须在 4 声部基础闭环稳定后再扩展。
