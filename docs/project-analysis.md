# 高云 FPGA 选题二：实时多音色合成电子乐器引擎

## 1. 分析范围与资料结论

本分析基于 `D:/qqdownload/FPFG_COMPETITION` 中的高云 2026 FPGA 赛道选题指南、FPGA2026 赛题解读资料、Sipeed Tang 系列资料及当前 Gowin 工程文件。当前工程目标器件为 **GW5AT-60B / GW5AT-LV60PG484AC1/I0**，现有 RTL 只有一个 `mux_2` 组合逻辑例程，尚未实现赛题功能。

赛题核心是：用 FPGA HDL 完成从演奏交互采集到 I2S 音频输出的纯硬件实时合成链路。音频不能依赖软核、MCU、上位机或预录 PCM；输出必须由实时控制量逐样本、逐声部生成。

## 2. 赛题验收指标

### 基础要求（必须闭环）

1. 至少 2 个独立可控演奏维度，例如音高/按键与力度，或音高与滑音/音色。
2. 交互动作能被 FPGA 稳定解析为选音、触发、拨弦、力度等控制事件。
3. FPGA HDL 完成实时音频合成，可选波表、加法合成、FM 或物理建模。
4. 通过 I2S 输出到 DAC/音频解码器。
5. 基础复音数不少于 4，支持独立声部同时发声。
6. 控制信号到音频输出总延迟不超过 10 ms。
7. 禁止直接播放预录 PCM、预置推流或整段录音触发。

### 推荐扩展（按工程风险逐步实现）

- 32 路以上复音或 32 路以上独立合成分量。
- 力度、滑音、颤音等至少 3 维表情控制。
- 至少 2 种音色切换。
- FPGA 内部混响、延迟、合唱等效果器。
- 演奏延迟压缩到 5 ms 以内，且延迟确定、无明显抖动。
- LED 曲目指引、波形/频谱/李萨如可视化。

## 3. 建议的系统链路

```text
交互传感器/按键
        │
        ▼
输入采集与去抖/滤波 ──► 事件检测与参数标定
        │                         │
        └──────────────► 演奏事件总线（note/velocity/gate/expr）
                                      │
                                      ▼
                            声部管理器（至少 4，目标 32）
                                      │
                                      ▼
             音高相位累加器 + 波表/加法/FM 振荡器 + ADSR 包络
                                      │
                                      ▼
                               多声部混音与限幅
                                      │
                                      ▼
                       音频效果器（延迟/混响/合唱，可选）
                                      │
                                      ▼
                   音频采样时序/左右声道打包 + I2S TX
                                      │
                                      ▼
                                  DAC/功放/扬声器

并行旁路：事件/音频状态 ─► LED/显示/频谱/波形可视化
```

### 3.1 时钟与采样坐标系

- `clk_sys`：FPGA 主时钟，负责输入、控制和音频流水线。
- `sample_tick`：音频采样使能，建议先以 48 kHz 为设计基准。
- `bclk`、`lrck`、`sdout`：I2S 位时钟、左右声道字选择和串行数据。
- 所有声部相位、包络和效果器状态只在 `sample_tick` 更新，避免不同模块各自计时造成漂移。
- 输入事件在 `clk_sys` 域采集并通过单一事件 FIFO/握手接口送入音频域；跨时钟域必须使用同步器或异步 FIFO。

### 3.2 数据格式约定（初版）

- 音频内部统一使用有符号定点数，建议 Q1.23 或 Q4.20；模块接口不得混用无符号音频值。
- `note_id` 使用 MIDI 风格整数音高；`phase_inc` 由音高查表或定点公式产生。
- `velocity`、表情参数和增益均使用明确位宽及饱和规则。
- 混音前保留足够保护位，混音后统一限幅/舍入到 I2S 输出位宽。

## 4. 模块边界

### 4.1 `rtl/io`

- `key_matrix_scan` / `touch_scan`：按键、电容或自研传感器采集。
- `input_debounce`：去抖、稳定判定。
- `sensor_calibration`：零点、阈值和力度标定。
- `i2s_tx`：标准 I2S 主机发送；先完成单音测试，再接入混音链路。

### 4.2 `rtl/control`

- `event_decoder`：把输入变化转换为 `NOTE_ON`、`NOTE_OFF`、力度和表情事件。
- `voice_manager`：空闲声部分配、抢占策略、释放状态管理。
- `instrument_ctrl`：音色选择、全局增益、效果器开关。
- `event_fifo`：将输入域事件与音频采样域解耦。

### 4.3 `rtl/audio`

- `phase_accumulator`：每个声部的相位累加器。
- `wavetable_osc`：正弦/锯齿/方波等查表振荡器；波表是波形数据，不是预录整段音频。
- `additive_osc` / `fm_osc`：扩展合成算法。
- `adsr_envelope`：起音、衰减、保持、释音。
- `voice_core`：单声部控制、振荡器和包络的组合。
- `mixer`：多声部求和、保护位、增益缩放和饱和。

### 4.4 `rtl/effects`

- `delay_line`：基于片上 RAM 的短延迟。
- `schroeder_reverb`：可选混响；先做旁路可用，再增加反馈网络。
- `chorus`：可选调制延迟。

### 4.5 `rtl/display` 与 `rtl/common`

- `led_guide`、`waveform_view`、`spectrum_analyzer`：可视化扩展。
- `clock_enable`、`saturator`、`cdc_sync`、`fixed_point_pkg`：所有模块共享的基础单元。

## 5. 推荐实现顺序

1. 保留 `mux_2` 作为最小综合 smoke test，建立统一顶层和约束。
2. 完成 `i2s_tx` + 固定频率测试音，验证 DAC、时钟和引脚。
3. 完成单声部波表振荡器，输入先用寄存器/仿真激励。
4. 接入 `NOTE_ON/OFF`、ADSR 和至少 4 声部混音。
5. 接入两种演奏维度（建议按键音高 + 压力/电位器力度）。
6. 增加音色切换、滑音/颤音，再扩展到 32 声部或 32 合成分量。
7. 最后实现效果器和显示，所有扩展都必须保持音频主链路可旁路、可测量。

## 6. 当前工程审计

- 已配置器件：GW5AT-60B。
- 已有源文件：`src/mux_2.v`、`src/FPGA_competition.cst`。

- 当前综合报告只使用 1 个 LUT、0 个寄存器、无时钟资源，说明工程尚未进入音频实现阶段。

## 8. 主要风险与待确认项

1. 需要尽快确认实际使用的 Tang Nano 20K、Primer 25K、Mega 60K 或 138K 板卡；器件型号与音频接口引脚不能仅凭项目文件推断。
2. 需要确认板上 DAC/Codec 型号、I2S 主从关系、MCLK 要求和模拟音频输出路径。
3. 需要确认交互传感器方案。为了降低周期风险，建议首版采用按键/电容触摸 + 压力或电位器两维方案。
4. 32 声部、效果器和显示会显著增加 RAM、乘法器和时序压力，必须在 4 声部闭环稳定后再扩展。
