# 两人协作与 AI 任务边界

## 核心规则

使用 AI 不会自动造成重复；重复通常来自任务描述没有限定“负责人、允许修改的文件、接口和验收条件”。每项任务必须同时写清这四件事：

1. 负责人和分支；
2. 允许修改的目录/文件；
3. 输入输出接口；
4. 可执行的完成判据。

任何任务都不能用“把整个项目做好”作为目标。

## 两人分工

| 负责人 | 固定边界 | 主要文件 |
|---|---|---|
| A：平台与集成 | Gowin 工程、器件/IP、时钟/复位、I2S、正式顶层、板卡下载与上板记录 | `FPGA_competition.gprj`、`src/top.v`、`src/*.cst`、`ip/`、`rtl/io/i2s_tx.v` |
| B：音频核心 | 相位累加器、波表/振荡器、ADSR、声部管理、混音和效果器，以及对应仿真 | `rtl/audio/`、`rtl/effects/`、`tb/audio_*` |
| 临时成员 C（可选） | 输入适配、按键/电位器、测试脚本、频谱和文档证据 | `rtl/control/`、`tb/control_*`、`scripts/`、`docs/evidence/` |

阶段性调整：A 先完成固定测试音和 I2S；B 同时在仿真中完成音频核心；基础音频闭环后，A 负责把输入硬件接到稳定事件接口。C 不放在关键路径上。

## 冻结的交接接口（v0）

交互模块不直接操作振荡器寄存器，只产生演奏事件：

```text
note_event:
  valid       : 1 bit, one-cycle pulse
  note_id     : 7 bit
  note_on     : 1 bit
  velocity    : 8 bit
  expression1 : 8 bit
  expression2 : 8 bit
  expression3 : 8 bit
  instrument  : 2 bit
```

音频核心不直接驱动引脚，只产生采样数据：

```text
audio_sample:
  sample_ce : 1 bit
  pcm_l/r   : signed 24 bit (内部可保留保护位)
```

`note_event` 可以先由 testbench 产生，之后再替换成按键、压力或电位器适配器；`audio_sample` 可以先接固定测试音，再接合成核心。只要接口不变，输入方案和合成算法可以独立更换。

## 分支与合并

- A 使用 `feat/platform-i2s`，B 使用 `feat/audio-core`；不得在同一工作区同时改同一文件。
- `main` 只接受可综合、带测试结果的提交。
- A 是顶层集成负责人；B 的 RTL 通过接口测试后，由 A 在集成分支接入，不让两个人同时编辑 `src/top.v`。
- 每个提交只解决一个小问题，例如 `feat: add i2s transmitter` 或 `test: add adsr assertions`。
- 合并前必须说明：改了哪些文件、接口是否改变、运行了什么仿真/综合、结果是什么。

如果两个人在同一台电脑上工作，最好分别使用 Git worktree；至少也要先提交、切换分支后再交给另一人。不要让两个 AI 会话同时在共享目录里编辑文件。

两个人都使用 AI 完全可以，但每次对话都要把任务卡放在第一条消息里，并明确“只改这些文件”。不要使用“继续完善项目”“把音频做好”这类没有边界的请求。AI 完成后先停在分支提交，另一人或集成人再审查和合并；不要让 AI 直接把两个未完成模块拼到 `main`。

## 给 AI 的任务模板

```text
任务：实现 <一个明确模块>
负责人/分支：<姓名> / <branch>
允许修改：<明确文件列表>
禁止修改：<其他目录，尤其是顶层和另一人的模块>
接口：严格遵守 docs/team-workflow.md 的 v0 接口
完成条件：<仿真、断言、综合或文件检查>
如果发现接口不够：先报告，不要擅自改接口或扩大文件范围
完成后报告：变更文件、测试命令、结果、已知风险
```

## 第一阶段任务切片

1. A：建立 138K 当前器件的最小顶层和 I2S TX testbench；输入先接固定 1 kHz 样本。
2. B：实现相位累加器、波表振荡器和单声部 ADSR；testbench 只使用 `note_event`。
3. A：完成固定测试音的工程综合和上板准备。
4. B：扩展 4 声部混音，并提交采样值、频率和包络测试结果。
5. A：集成 `audio_sample -> i2s_tx`；B 不修改顶层。
6. 基础链路稳定后，再由 A 接入真实输入，B 扩展 32 声部和效果器。

每项完成后先合并，再开始下一项依赖任务。这样既能并行开发，也能让每次合并都保留一个可回退的工作状态。
