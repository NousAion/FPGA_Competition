# 放音链路分析与实现规划

## 1. 文档目的

本文将“放音部分”从最终效果反推到硬件模块、信号链路、开发顺序和验收标准。放音部分不是播放预录音频，而是从演奏输入开始，由 FPGA 逐样本实时生成音频，再经 I2S 输出到 DAC/Codec。

## 2. 最终目标

系统应实现以下效果：

- 按键、触摸、压力或旋钮等输入能够触发指定音符；
- 单声部音高可实时变化；
- 至少 4 个独立声部同时发声，目标扩展到 32 声部；
- 每个声部具有独立频率、相位、音量和包络状态；
- 支持 ADSR 包络，按下和释放时无明显爆音；
- 至少支持两种音色切换；
- 音频通过 I2S 输出到板载 DAC/Codec；
- 控制到音频输出延迟满足赛题要求；
- 测试模式能够输出多路不同频率，观察对应独立谱峰，证明音频为实时合成而非预录 PCM 播放。

## 3. 总体信号链路

```text
演奏输入
  -> 输入采集与消抖/滤波
  -> 事件识别与参数归一化
  -> 声部管理器
  -> 多个 voice_unit
  -> 多声部混音器
  -> 音频效果器
  -> 限幅、格式转换和左右声道封装
  -> I2S 发送器
  -> 板载 DAC/Codec
  -> 耳机或扬声器
```

## 4. 主要模块

### 4.1 输入采集模块

负责按键、触摸、压力、旋钮或其他传感器的采样，输出统一控制事件：

```text
note_on, note_off, note_id, velocity, expression
```

原始输入不能直接驱动振荡器，需要完成消抖、阈值判断、ADC 数值归一化和参数平滑。

### 4.2 事件识别模块

将输入转换为稳定的音符和表情参数。至少需要处理按键消抖、触摸状态、力度值和旋钮变化。后续可增加滑音和颤音参数。

### 4.3 声部管理器

负责分配空闲声部、处理 `note_on`/`note_off`、记录音符和力度、释放声部，以及必要时进行声部抢占。每个声部至少保存：

- 音符或频率控制字；
- 当前相位；
- 包络状态；
- 音量/力度；
- 音色选择；
- 表情参数。

### 4.4 `voice_unit`

推荐的单声部结构：

```text
phase_accumulator
  -> waveform_lookup
  -> ADSR_envelope
  -> velocity/gain
  -> voice_sample
```

相位累加器使用：

```text
phase_next = phase + phase_step
phase_step = frequency * 2^PHASE_WIDTH / sample_rate
```

波表高位用于查表。声部模块应参数化，先实例化 4 个，再扩展到 8、16、32 个；不需要重复编写 32 份代码。

### 4.5 混音器

将所有活动声部相加：

```text
mix = voice_0 + voice_1 + ... + voice_N
```

必须进行位宽扩展、溢出保护、饱和处理和输出增益控制，不能直接截断高位，否则多声部同时发声时会产生明显失真。

### 4.6 音色与效果器

音色可以通过不同波表、谐波参数、包络或滤波参数实现。建议按以下顺序开发效果器：

```text
直通 -> 音量控制 -> 简单延迟 -> 简化混响 -> 合唱
```

短延迟线优先使用片上 BSRAM，首版不依赖 DDR3。效果器放在混音之后，并逐项验证音量、溢出、延迟和音频连续性。

### 4.7 I2S 发送器

将并行音频样本转换为串行 I2S：

```text
audio_sample
  -> 左/右声道寄存器
  -> I2S 移位寄存器
  -> BCLK + LRCLK + SDATA
```

必须根据板卡 Codec 资料确认采样率、位宽、BCLK、LRCLK 极性、数据相对 WS 的偏移、Codec 复位和功放使能时序。

## 5. 推荐开发工作流

### 阶段 1：先打通板卡音频通路

用 FPGA 输出固定 1 kHz 正弦波或方波，经 I2S 到 DAC/Codec。验收 BCLK、LRCLK、SDATA、采样率和实际声音。

### 阶段 2：实现单声部振荡器

先用测试按键或仿真事件改变音符，确认频率、波形和音符切换正确。

### 阶段 3：加入 ADSR

验证 `Attack -> Decay -> Sustain -> Release`，重点检查按下/释放无爆音、状态不死锁、新音符可重新触发。

### 阶段 4：扩展到 4 声部

使用 C4、E4、G4、C5 等固定测试音符同时发声，并用频谱观察多个谱峰，先完成基础要求。

### 阶段 5：接入真实交互

至少实现两个独立控制维度，例如按键负责音符/触发，旋钮或压力值负责力度/音量。

### 阶段 6：逐级扩展声部

按 `4 -> 8 -> 16 -> 32` 的顺序扩展，每次记录 LUT、FF、DSP、BSRAM、时序裕量和音频延迟。

### 阶段 7：加入音色和效果器

先完成两种音色自由切换，再按直通、延迟、混响、合唱的顺序加入效果器。

### 阶段 8：准备现场测试模式

为各声部配置不同固定频率，输出多路可区分音频，配合频谱观察独立谱峰，并保留 RTL 代码说明每个声部的实时生成过程。

## 6. 推荐接口

### 控制事件接口

```text
note_on      音符触发
note_off     音符释放
note_id      音符编号
velocity     力度
expression   表情参数
```

### 音频数据接口

```text
sample_valid
sample_left
sample_right
```

`audio_engine`、声部、混音器和效果器应尽量与板卡无关；PLL、I2S 引脚、Codec 控制和约束文件放在板卡适配层。

## 7. 放音部分验收清单

- [ ] 固定测试音频可以经 I2S 播放；
- [ ] I2S 时钟和采样率正确；
- [ ] 单声部音高正确且可变调；
- [ ] ADSR 工作正常，切换无明显爆音；
- [ ] 至少 4 个声部可同时发声；
- [ ] 目标声部数的测试模式可运行；
- [ ] 至少两种音色可切换；
- [ ] 计划中的力度、滑音、颤音控制有效；
- [ ] 混音无严重削波和溢出失真；
- [ ] 控制到音频输出延迟满足指标；
- [ ] I2S 长时间运行无丢样或断音；
- [ ] 测试模式能观察多个独立谱峰；
- [ ] RTL 能证明音频由实时振荡、包络和混音生成，而非播放预录音频。

## 8. 设计原则

1. 先验证“固定样本 -> I2S -> Codec -> 扬声器”，再增加合成算法。
2. 先完成单声部，再参数化扩展到多声部。
3. 音频主链路必须固定时序，显示和调试逻辑不能阻塞音频采样。
4. 先用片上 BSRAM 完成波表和短延迟，不把 DDR3 作为首版依赖。
5. 所有声部状态和控制参数应可观测、可复位、可仿真。
6. 每增加一个功能都重新做仿真、综合、时序和长时间上板测试。
